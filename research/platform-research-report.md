# 跑团平台与开源项目调研对比报告

> 调研日期：2026-05-03
> 对比基准：COC七版跑团平台（本项目）
> 技术栈：Vue 3 + NestJS + PostgreSQL + Redis + WebSocket + AI辅助

---

## 一、市面上主流跑团平台功能对比

### 1.1 国际VTT平台

| 平台 | 定位 | COC支持 | 核心特色 | 技术架构 | 与本项目差异/借鉴点 |
|------|------|---------|---------|----------|-------------------|
| **Roll20** | 最大在线VTT | 有COC官方/社区Sheet | 云托管、浏览器即开即玩、海量素材市场、动态光照/视野线 | Ruby on Rails + 自研引擎，WebRTC语音 | 其**动态视野线（Fog of War / Line of Sight）**和**骰子塔特效**值得参考；但我们自托管+AI辅助KP是其没有的差异化 |
| **Foundry VTT** | 自托管VTT标杆 | COC 7e系统非常完善 | 模块化设计（1000+社区模块）、服务器自托管、数据完全私有、强大的宏和脚本系统 | Node.js + Electron + Socket.io + PixiJS渲染 | **最值得深度参考**：其插件/模块机制（modules）让KP可热装载扩展；**Dice So Nice** 3D骰子物理引擎；**Simple Calendar** 游戏内时间线系统 |
| **Fantasy Grounds** | 老牌付费VTT | 有官方COC规则包 | 官方授权规则书集成（自动查询规则）、GM-only视图 | C++/Lua | 其**规则书电子化查询**和**GM私有面板**设计可借鉴，但技术栈老旧 |
| **Owlbear Rodeo** | 极简VTT | 无专用规则，通用网格 | 2分钟开房、纯前端、无账号、P2P文件共享、聚焦地图和棋子 | Vanilla JS + WebRTC + Canvas | 其**极简开房流程**和**纯浏览器P2P同步**理念值得借鉴，适合降低新人门槛 |
| **Above VTT** | DND Beyond增强插件 | DND专用 | 深度集成DND Beyond角色卡，一键导入 | Chrome Extension + DND Beyond API | 我们的COC平台也可以考虑**支持Excel/空白卡一键导入**，类似思路 |
| **Talespire** | 3D VTT | 通用 | 3D建筑搭建、物理渲染、沉浸感强 | Unity WebGL | 3D部分过重，但**3D骰子动画**和**场景沉浸感**可作为远期参考 |

### 1.2 国内跑团平台

| 平台 | 状态 | 核心功能 | 与本项目对比 |
|------|------|---------|-------------|
| **猫爷TRPG** (maoyetrpg.com) | 活跃运营 | 房间制跑团、骰子机器人、角色卡、图片/音乐分享、支持COC/DND规则 | 有角色卡但不够自动化；**无AI辅助KP**；无完整战斗轮；我们的装备位置状态和行动系统是其没有的 |
| **面团TRPG** (doughbot.cn) | 已停运（约2023年） | 早期QQ机器人起家，后做Web平台，主打COC/DND | 前车之鉴：过度依赖单一渠道（QQ），Web端体验割裂 |
| **COCBot / TRPG盒子** | 活跃（Discord/QQ机器人） | 纯机器人，骰点、技能查询、疯狂症状抽取 | 我们的平台应**兼容/提供机器人接入能力**（WebSocket桥接QQ/Discord Bot），覆盖习惯用机器人的用户 |
| **TRPG云** | 较小众 | 轻量房间+骰子 | 功能较单薄 |

## 二、GitHub开源项目深度分析

### 2.1 与COC/DND直接相关的开源项目

| 项目 | Star | 语言/框架 | 核心能力 | 可借鉴点 |
|------|------|----------|---------|---------|
| **kakaroto/Beyond20** | 2.5k+ | JS (Browser Extension) | DND Beyond ↔ VTT双向同步角色数据、骰子结果渲染 | **角色卡数据格式标准化**：可参考其插件架构，让我们平台也能成为"数据源"，向其他VTT输出角色卡 |
| **kame-ta** / TRPG相关Bot | 数百 | Node.js/Python | Discord/QQ机器人框架 | **机器人+Web双端互通**：同一房间同时支持Web用户和Bot用户 |
| **Cthulhu-Chronicle** 系列 | 较少 | 各异 | COC角色卡生成器、单人Solo工具 | 角色卡PDF导出、Solo模式（AI KP单人跑团）可作为远期方向 |
| **Open5e** | 2k+ | Vue + Django | DND 5e SRD开源参考站，规则查询API | **规则数据库开放API**：我们已规划了技能/职业/武器种子数据，可进一步包装成REST API供机器人/第三方调用 |

### 2.2 通用VTT开源项目

| 项目 | Star | 技术栈 | 核心亮点 | 对本项目的技术借鉴 |
|------|------|--------|---------|------------------|
| **foundryvtt** (闭源但模块开源) | - | Node.js + PixiJS | 模块系统：`module.json` + `hooks.on` 事件机制，社区开发扩展无需改核心 | **重点参考**：我们的"AI辅助开关"和"模组配置"可借鉴其**Hooks系统**设计，让扩展插件能在不改动核心代码的情况下注入行为 |
| **mrkmg/node-trpg** | ~200 | Node.js + Socket.io | 早期Node.js TRPG后端，房间+消息+骰子 | 参考价值有限，技术老旧，但验证了WebSocket跑团的基本模型 |
| **owlbear-rodeo/owlbear-rodeo-legacy** | 1.5k+ | TypeScript + Firebase | 开源旧版，纯前端+Firebase实时同步 | **状态同步机制**：其CRDT/乐观锁同步策略对WebSocket房间状态同步有参考意义 |
| **Kanka.io** (部分开源) | - | Laravel + Vue | RPG世界构建（地点、人物、组织时间线）、支持"战役（Campaign）"层级 | **世界构建模块**：我们的"复盘系统"可以升级为"战役维基"，让KP能管理NPC、地点、组织关系图 |
| **Dungeon-Revealer** | 1k+ | Node.js + React | DM视角 vs 玩家视角分离、地图迷雾 | **双重视角**：KP/DM能看到全部，玩家只能看到已揭示区域。我们的线索共享已类似，但地图迷雾可借鉴 |

### 2.3 地图与战斗轮相关开源项目

| 项目/库 | 用途 | 技术 | 借鉴点 |
|---------|------|------|--------|
| **fabric.js** | Canvas交互库 | JS | 我们的地图系统可直接使用fabric.js实现Token拖拽、视野绘制、网格对齐 |
| **PIXI.js** (Foundry同款) | 2D WebGL渲染 | JS | 如需高性能大规模地图/特效，可考虑用PixiJS替代DOM方案 |
| **grid-engine** | Phaser网格移动 | JS | 战斗轮格子移动规则引擎，适合DND网格战；COC虽非网格战，但**追逐轮（Chase）**可用 |
| **Dice-So-Nice** (Foundry模块) | 3D物理骰子 | Three.js | 如果后期要加视觉体验，可用Three.js做3D骰子动画 |

## 三、功能清单对比矩阵

| 功能维度 | 本项目(Phase1完成) | Roll20 | Foundry | 猫爷 | 可补充借鉴 |
|---------|-------------------|--------|---------|------|-----------|
| **角色卡系统** | 完整COC 7e（18表）、自动计算衍生属性 | 社区Sheet，计算有限 | 官方/社区Sheet极完善，宏支持 | 基础填写，无自动计算 | **参考Foundry宏系统**：允许KP写自定义公式和自动化 |
| **车卡向导** | 已做向导式车卡 | 手动填写为主 | 有向导 | 无 | **参考DND Beyond**：分步向导+实时规则校验 |
| **AI辅助KP** | 核心差异化：动作识别/线索/场景/NPC/战斗 | 无 | 有AI模块（如Moulinette + AI） | 无 | 这是我们最大差异化，**保持领先**；参考Foundry模块热插拔机制，让AI功能可独立开关 |
| **实时通信** | WebSocket (Socket.io) | WebRTC + 自研 | Socket.io | WebSocket | **参考Foundry的音频/视频集成**：可选Jitsi Meet或自托管语音 |
| **战斗轮** | 规划中 | 基础回合制 | 非常完善（先攻/条件/范围/自动计算） | 无 | **参考Foundry Combat Tracker**：条件（Prone/Bleeding等）自动化、范围测量（Cone/Line/Radius） |
| **地图系统** | 规划中 | 完善（网格/动态光/视野） | 顶级（动态光/天气/动画/3D地形） | 基础图片共享 | **参考Dungeon-Revealer的双视角+迷雾**：KP图层 vs 玩家图层 |
| **装备/物品** | 有位置状态（背包/手持/身上） | 基础物品栏 | 非常灵活（重量/容量/使用次数） | 无 | **参考Foundry物品使用逻辑**：消耗品次数、武器装填/卡壳状态联动 |
| **骰子系统** | d100+奖惩骰+幸运+SAN | 多种骰子语法 | 宏骰子/3D物理骰 | 基础骰点 | **参考Dice So Nice**：3D骰子动画提升仪式感 |
| **线索共享** | 有（共享给某人/团队） | 无专用 | 可用Journal+权限模拟 | 无 | **参考Kanka的时间线**：线索按时间线组织，而非纯列表 |
| **复盘系统** | 规划中（个人/团队时间线+线索图谱+AI复盘） | 无专用 | 无专用 | 无 | **这是我们的差异化方向**，参考Kanka的时间线和Obsidian的关系图谱 |
| **子房间/私密** | 已规划 | 无（只有页面层） | 可通过场景权限模拟 | 无 | 我们的子房间设计较领先，**继续深化** |
| **语音/视频** | 未规划 | 内置 | 可选模块 | 无 | **建议引入Jitsi集成**或WebRTC，避免依赖第三方语音软件 |
| **PDF导出** | 未规划 | 无 | 有模块支持 | 无 | **参考Excel空白卡导出**：让玩家能打印线下使用 |
| **规则查询** | 未规划 | 手动查书 | 有Compendium可查询 | 无 | **建议做规则速查面板**： hover技能/状态/法术时弹出规则说明 |
| **插件/扩展** | 未规划 | 无 | 核心优势（模块系统） | 无 | **高优先级借鉴Foundry模块系统**：让社区可开发扩展 |

## 四、技术方案对比与建议

### 4.1 架构层面

| 维度 | 本项目 | Foundry VTT | 建议 |
|------|--------|-------------|------|
| 前后端 | Vue 3 + NestJS | Vanilla JS + Node.js | 我们的技术栈更现代，保持 |
| 实时通信 | Socket.io | Socket.io | 一致，可复用其房间/场景同步逻辑 |
| 渲染方案 | DOM-based | PixiJS (WebGL) | 当前DOM够用；如地图规模变大，考虑用**Fabric.js**做Canvas层 |
| 模块化 | 未做 | module.json + Hooks | **重点引入**：定义`coc-module.json`规范，支持Hooks注册 |
| AI集成 | 可配置OpenAI兼容API | 社区模块各做各的 | 我们的统一AI配置面板是优势，保持 |

### 4.2 数据模型层面

| 维度 | 本项目 | 参考方案 | 建议 |
|------|--------|---------|------|
| 角色卡 | Prisma Schema 18表 | Foundry Actor/Item系统 | 引入**Actor + Item模板化**：技能、物品、法术都是Item的子类型，便于扩展 |
| 模组/战役 | Campaign + Scene + Module | Foundry World + Adventure | 参考其**冒险（Adventure）导出/导入**：让KP能打包分享整个模组 |
| 消息/日志 | Message表 | Foundry ChatMessage | 我们的消息系统可加入**骰子结果卡片化渲染**（类似Discord Embed） |

## 五、可直接借鉴落地的具体建议

### 高优先级（Phase 2-3可落地）

1. **战斗轮Combat Tracker**（参考Foundry）
   - 先攻排序、回合/轮次计数
   - 条件效果（流血/眩晕等）计时器
   - 快速行动按钮（攻击/移动/闪避/反击）

2. **规则速查面板**
   - 鼠标hover技能名称弹出基础值+规则说明
   - 法术/恐惧/疯狂表格速查
   - 这是我们比国际平台更懂中文COC玩家的优势

3. **骰子结果卡片化**
   - 检定结果不只是文字，而是结构化卡片（技能名/目标值/出目/成功等级）
   - 支持"奖励骰/惩罚骰"可视化展示

4. **地图双重视角**（参考Dungeon-Revealer）
   - KP能看到全部+编辑
   - 玩家只看到"已揭示"区域
   - Token拖拽、网格对齐

### 中优先级（Phase 3-4）

5. **模块/插件系统**（参考Foundry module.json）
   - 定义简单的`manifest.json`规范
   - 允许第三方注册新的AI行为、骰子皮肤、角色卡主题
   - 前端通过动态`import()`加载

6. **战役时间线/维基**（参考Kanka）
   - 将"复盘"升级为"战役维基"
   - NPC、地点、组织、线索都以词条形式存在
   - 关系图谱可视化

7. **音频/语音集成**
   - 集成Jitsi Meet iframe 或自托管语音
   - 背景音乐/音效面板（参考Syrinscape）

8. **角色卡PDF导出**
   - 对接空白卡CY20.02.2格式
   - 支持打印和线下使用

### 低优先级/远期（Phase 5+）

9. **3D骰子动画**（参考Dice So Nice）
10. **Solo单人模式**（AI KP全程带单人团）
11. **跨平台Bot桥接**（QQ/Discord机器人接入同一房间）
12. **移动端适配优化**（参考Owlbear Rodeo的移动端触控）

## 六、竞品空白点（我们的机会）

通过对比发现，以下需求在现有平台中**没有很好被满足**，正是我们平台的差异化空间：

| 空白点 | 说明 |
|--------|------|
| **AI辅助KP一体化** | 国际平台无原生AI，国内平台无此功能。我们的"可开关AI辅助"是独特卖点 |
| **中文COC原生体验** | Roll20/Foundry的COC都是社区翻译/移植，原生中文车卡向导+规则速查体验更好 |
| **装备位置状态+行动限制** | 我们的"手枪在包里不能开"这类行动逻辑，在现有平台中没有 |
| **线索共享+复盘一体化** | 从获得线索→共享→串联→AI复盘，形成完整闭环 |
| **子房间/场景隔离** | 适合分头调查、战斗轮并行，现有平台没有此设计 |

## 七、总结

**最值得深度研究的项目：Foundry VTT**
- 其模块系统（module.json + Hooks）是扩展性设计的最佳实践
- COC 7e支持非常完善，可直接体验其车卡/战斗/骰子流程作为功能对标
- 自托管模式与我们一致，技术栈相近（Node.js + Socket.io）

**最易借鉴的轻量方案：Owlbear Rodeo + Dungeon-Revealer**
- 极简开房和地图双视角适合快速原型验证

**最大差异化保持方向：AI辅助KP + 中文原生COC体验 + 线索复盘闭环**
- 这是国际大平台（Roll20/Foundry）不会专门为中国COC玩家做的
- 也是国内平台（猫爷等）没有技术能力做的
