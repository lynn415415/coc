# VTT深度调研与功能/UI对齐报告

> 调研基准日：2026-05-03
> 基于对 Roll20 / Foundry VTT / Owlbear Rodeo / 猫爷TRPG / Kanka 的深度体验与代码级分析
> 对照项目：COC七版跑团平台（Vue 3 + Naive UI + NestJS + Socket.io）

---

## 第一部分：各VTT平台深度体验分析

### 1.1 Foundry VTT —— 最值得对标的自托管VTT

**整体UI架构**
Foundry采用**深色主题（#1a1a2e / #16213e）**为主，三栏布局：
- **左侧边栏**（可折叠）：Actors（角色）、Items（物品）、Journal（日志）、Tables（表格）、Playlists（音频）、Compendium（资料库）
- **中间主画布**：地图/场景渲染区（Canvas/PixiJS）
- **右侧边栏**（可折叠）：Chat（聊天）、Combat（战斗轮）、Scenes（场景列表）、Actors Directory

**核心UI交互模式**
1. **拖拽即关联**：从左侧Actors拖拽Token到地图 = 创建场景Token；从Journal拖拽到Chat = 分享线索
2. **右键上下文菜单**：Token右键 → 显示/隐藏、编辑HP、分配状态条件
3. **折叠区块（Collapsible Sections）**：角色卡每个区块（属性/技能/装备）可独立折叠，保持页面整洁
4. **宏快捷栏**：屏幕底部一排按钮格（类似我们的快速面板，但固定在底部）
5. **标签页内嵌子标签**：角色卡顶部有Main/Inventory/Biography等主Tab，技能区内部再有Combat/Knowledge等子分类

**COC 7e系统具体实现**
- **角色卡（Actor Sheet）**：左侧头像+姓名，中间属性大数字展示（STR/CON等），右侧技能列表按分类折叠
- **技能展示**：每个技能一行，左侧技能名，中间基础值，右侧总成功率，hover时显示"掷骰"图标
- **战斗轮（Combat Tracker）**：右侧栏，显示先攻顺序（头像+名字+HP条+先攻值），当前回合高亮，GM可拖拽调整顺序
- **疯狂表**：内置疯狂症状表，一键抽取，结果自动输出到Chat
- **追逐轮（Chase）**：专门的追逐卡片，支持障碍物、速度计算

**对我们最大的借鉴**
- **模块系统（module.json + Hooks）**：第三方扩展无需改核心代码
- **角色卡折叠区块**：避免技能列表过长导致页面臃肿
- **Chat卡片化骰子结果**：不仅是文字，而是带颜色、带图标的结构化卡片
- **Combat Tracker常驻右侧栏**：战斗状态时自动展开，非战斗时收起

### 1.2 Roll20 —— 最大在线VTT的用户教育标杆

**整体UI架构**
- **顶部工具栏**：选择/测量/绘图/文本/骰子按钮
- **左侧图层控制器**：Map & Background / GM Overlay / Tokens / Dynamic Lighting
- **中间画布**：地图渲染区，支持网格（Square/Hex/Iso）
- **右侧多标签面板**：Chat / Journal / Card Decks / Jukebox / Collection

**核心UI交互模式**
1. **手风琴式角色卡**：每个区块（属性/攻击/技能）可点击展开/收起，一个页面内塞下大量信息
2. **Token状态栏**：Token右下角可叠放状态图标（数字徽章/颜色圆点/条件图标）
3. **动态光照（Dynamic Lighting）**：Token自带光源半径，墙线阻挡，玩家只能看到光源范围内
4. **骰子宏按钮条**：角色卡底部一排可自定义宏按钮，点击即掷骰
5. **Turn Order浮窗**：可放在任意位置，头像+名字+先攻值，GM点击"下一回合"

**COC 7e实现特点**
- **社区Sheet**：由社区维护，非官方。有自动计算但更新滞后
- **技能列表**：纯文本列表+输入框，无快捷掷骰按钮（需要宏）
- **角色卡底部宏条**：预设 /r 1d100<@{skillname} 这类宏

**对我们最大的借鉴**
- **Token状态徽章系统**：HP变化时Token上直接显示数字
- **角色卡手风琴折叠**：避免一次性展示全部技能
- **骰子宏的可视化按钮**：把常用检定做成角色卡底部的按钮条
- **动态光照/迷雾概念**：KP揭示 vs 玩家视野的分离

### 1.3 Owlbear Rodeo —— 极简主义的UI教科书

**整体UI架构**
- **顶部极窄工具栏**：选择/平移/画笔/测距/骰子/迷雾
- **中间几乎全屏画布**：地图占据90%空间
- **右侧资产抽屉**：可折叠，分Token/地图/笔记三类
- **无角色卡系统**：纯视觉VTT，所有规则由口头处理

**核心UI交互模式**
1. **两步开房**：打开网站 → 输入房间名 → 复制链接邀请。全程无需注册
2. **Token从资产库拖拽到地图**：右侧抽屉选中Token，拖到画布上即创建
3. **右键Token**：编辑名字/HP/大小/隐藏
4. **迷雾绘制**：GM用画笔在地图上涂"迷雾"，玩家看不到被涂区域
5. **骰子浮层**：点击骰子按钮弹出简洁的骰子面板，掷出后结果以聊天气泡形式出现

**对我们最大的借鉴**
- **极低门槛的开房流程**：我们的跑团房间应该支持"一键开房+复制链接"
- **画布优先的布局**：跑团时地图应该占据视觉中心，UI元素尽量靠边/可折叠
- **迷雾的直觉化操作**：直接用画笔涂抹而非复杂的多边形工具
- **右侧资产抽屉**：Token、地图、音乐等素材以抽屉形式管理，不占用主空间

### 1.4 猫爷TRPG —— 国内跑团的本土化参考

**整体UI架构**
- **左侧房间列表**：类似QQ的会话列表
- **中间聊天区**：顶部房间信息，中间消息流，底部输入框+骰子按钮
- **右侧成员/角色卡**：当前房间成员及简略角色信息

**核心功能**
1. **骰子机器人语法**：.rd100、.ra侦查 等命令式掷骰
2. **图片/音乐插入**：支持在聊天中发送图片和BGM
3. **角色卡基础填写**：文本框为主，无自动计算
4. **日志导出**：跑团记录可导出为文本

**问题与教训**
- 角色卡和聊天割裂：角色卡不能直接在聊天区掷骰
- 无地图系统：纯文字跑团，场景感弱
- 无战斗轮支持：先攻、回合全靠口头

**对我们最大的借鉴**
- **骰子命令语法文化**：国内玩家习惯 `.ra技能` 这种语法，我们的聊天区应该支持类似快捷指令
- **日志导出功能**：跑团记录导出为PDF/文本是刚需
- **BGM插入**：场景切换时自动播放背景音乐增强氛围

### 1.5 Kanka —— 战役管理与复盘的关系图谱典范

**整体UI架构**
- **顶部导航**：Campaign / Entities / Timeline / Maps / Calendars
- **左侧实体类型树**：Characters / Locations / Organizations / Items / Journals / Quests
- **中间内容区**：类似Wiki的文章页，支持@引用其他实体
- **右侧关系图谱**：当前实体的关联网络图

**核心功能**
1. **实体（Entity）系统**：一切皆为实体，有统一模板（名字、类型、标签、隐私设置）
2. **@引用语法**：在文章中写 @Alex_Mullen 即可链接到对应角色
3. **关系图谱**：自动根据引用和手动设置的关系生成力导向图
4. **时间线（Timeline）**：可创建多条时间线，事件按时间排序，支持纪元/年代
5. **隐私层级**：公开 / 仅管理员 / 仅特定角色可见

**对我们最大的借鉴**
- **线索即实体**：每条线索都是一个可引用的Entity，支持@引用
- **时间线复盘**：跑团事件按时间轴组织，支持"剧本时间"和"现实时间"双轴
- **关系图谱**：线索-地点-NPC-玩家之间的关联可视化
- **隐私层级**：线索可以设置为"仅某人可见"、"已分享"、"团队公开"

## 第三部分：前端UI具体参考建议

### 3.1 色彩体系升级建议

**现状分析**
当前主色 `#8B4513`（SaddleBrown），背景 `#f5f5f0`，整体偏暖黄。这是好的COC氛围色（老旧纸张感），但跑团房间需要更强的**功能区分度**。

**参考Foundry/Roll20的暗色主题**
跑团房间（CampaignRoom）建议采用**可选暗色模式**，原因：
1. 长时间跑团（3-6小时）暗色更护眼
2. 地图/Token在暗色背景上对比度更好
3. 暗色更有"神秘/克苏鲁"氛围

**建议色彩方案（保持品牌色+增加暗色模式）**

```css
/* 浅色模式（车卡/列表等管理页） */
--color-primary: #8B4513;
--color-bg-page: #f5f5f0;
--color-bg-card: #ffffff;
--color-text-main: #333333;
--color-border: #e0e0dc;

/* 暗色模式（跑团房间） */
--color-bg-dark: #1a1a2e;
--color-bg-panel: #16213e;
--color-bg-elevated: #0f3460;
--color-text-light: #e94560;  /* 强调色：暗红 */
--color-border-dark: #2a2a4a;
```

**具体组件着色**
| 元素 | 浅色 | 暗色（跑团房） | 参考来源 |
|------|------|---------------|---------|
| 场景Banner | `#2c2c2c` 白字 | `#0f3460` 渐变 | Foundry场景标题 |
| 成员列表背景 | `#f5f5f0` | `#16213e` | Foundry侧边栏 |
| 聊天区背景 | `#fafaf8` | `#1a1a2e` | Roll20/Foundry Chat |
| 检定成功 | `#18a058` 绿 | `#4ade80` 亮绿 | Foundry success color |
| 检定失败 | `#d9534f` 红 | `#f87171` 亮红 | Foundry failure color |
| 大成功 | 金色徽章 | 金色+脉冲动画 | Dice So Nice |
| 大失败 | 暗红色+抖动 | 暗红+抖动 | Dice So Nice |
| HP条 | `#d9534f` | `#e94560` | Roll20 |
| SAN条 | `#5bc0de` | `#38bdf8` | Foundry COC |
| MP条 | `#5cb85c` | `#4ade80` | Foundry COC |

### 3.2 跑团房间布局重构建议

**现状问题**
当前 [`CampaignRoom.vue`](frontend/src/views/CampaignRoom.vue) 是三栏固定布局（左220px成员/中flex聊天/右220px快速面板），聊天占据主视觉。但跑团的核心体验应该是**地图/场景为中心**。

**建议新布局（参考Foundry+Owlbear混合）**

```
┌─────────────────────────────────────────────────────────────┐
│  [≡] 场景: 阿卡姆图书馆          [语音] [设置] [成员3人在线] │  ← 顶部窄Bar
├──────┬────────────────────────────────────────────┬─────────┤
│      │                                            │         │
│ 成员 │                                            │ 快速    │
│ 列表 │          主画布（地图/场景）               │ 面板    │
│(可折 │                                            │(可折叠) │
│ 叠)  │                                            │         │
│      │                                            │         │
│      ├────────────────────────────────────────────┤         │
│      │  聊天流（半透明叠加层，可收到底部）        │         │
│      │                                            │         │
├──────┴────────────────────────────────────────────┴─────────┤
│  🎲 [快捷宏1] [快捷宏2] [快捷宏3] [快捷宏4] [快捷宏5] ...    │  ← 底部宏条
└─────────────────────────────────────────────────────────────┘
```

**布局细节**
1. **主画布占80%视觉**：默认显示地图，无地图时显示场景描述+氛围图
2. **聊天区可切换模式**：
   - **叠加模式**：半透明浮在主画布底部（适合地图跑团）
   - **分栏模式**：主画布右侧分出聊天列（适合纯文字团）
3. **左右边栏可折叠**：点击[≡]收起，最大化画布
4. **底部宏条常驻**：类似Foundry的Macro Bar，支持拖拽配置

**代码层面的建议**
在 [`CampaignRoom.vue`](frontend/src/views/CampaignRoom.vue) 中：
- 将 `.main` 区域改为 `position: relative`，画布绝对定位占满
- 聊天区增加 `position: absolute; bottom: 0` 的叠加模式
- 左右sidebar增加折叠按钮，用 `transition: transform 0.3s` 做平滑动画
- 新增底部 `.macro-bar { position: fixed; bottom: 0; height: 48px; }`

### 3.3 角色卡UI升级建议

**现状分析**
[`InvestigatorDetail.vue`](frontend/src/views/InvestigatorDetail.vue) 使用 `n-tabs` 做5个标签页（属性/技能/资产/装备/背景）。信息密度合理，但技能页在60+技能时会非常长。

**参考Foundry的折叠区块+Roll20的手风琴**

**建议重构方案**

**属性页（参考Foundry COC Sheet）**

│  └──┴──┘   │                                               │
├─────────────────────────────────────────────────────────────┤

## 第五部分：竞品差异化机会点（UI/UX层面）

通过对比分析，以下体验细节在现有平台中**未被满足**，是我们构建差异化体验的切入点：

1. **中文COC原生字体与排版**
   - 国际平台（Roll20/Foundry）的COC都是英文Sheet翻译版，中文字号/行高/排版未优化
   - **机会**：我们的角色卡使用更适合中文阅读的排版（行高1.6、合适的字号层级）

2. **"装备位置→行动可用性"的即时反馈**
   - 我们的核心设计：手枪在包里不能直接开枪
   - **UI表现**：快捷栏中武器图标灰色+提示"需先取用"，聊天区输入"开枪"时智能提示"武器在背包"
   - 这在任何VTT中都没有直观体现

3. **AI辅助的"轻打扰"设计**
   - 我们的AI是可开关的，但AI响应时不能阻塞聊天流
   - **UI表现**：AI思考中显示"..."微动画在角落，结果以折叠卡片形式插入聊天，用户可展开/忽略
   - 参考ChatGPT的流式输出，但更加克制

4. **线索的"物理感"**
   - 获得线索时不是纯文本通知，而是聊天区弹出"卡片翻转"动画，背面显示线索内容
   - 共享线索给其他玩家时，有"传递"动画效果
   - 这在现有平台中都没有

5. **复盘系统的"时间线+关系图"融合**
   - Kanka有时间线但没关系图，Obsidian有关系图但无时间线
   - **我们的设计**：时间线中的每个事件节点可展开为关系图，双视图自由切换
